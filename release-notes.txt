EarShield 6.0.8
================

* Debug log facility added. Plugin writes a timestamped log to
    Windows: %APPDATA%\TS3Client\plugins\EarShield_debug.log
    Linux:   ~/.ts3client/plugins/EarShield_debug.log
    macOS:   ~/Library/Application Support/TeamSpeak 3/plugins/EarShield_debug.log
  every line is flushed immediately so it survives even hard crashes.
* Crash handlers: SIGSEGV/SIGABRT/SIGBUS/SIGILL/SIGFPE plus
  std::set_terminate are wired to dump a backtrace and the message
  before propagating, so the next macOS crash on Settings or Check
  for Updates leaves a usable trace in the log.
* Menu handlers + UpdateChecker calls + all dialog ctors and
  show()/exec() are wrapped with try/catch + entry/exit logging.

EarShield 6.0.7
================

* Fix double-Qt rewrite bug (v6.0.6 regression): the macOS dylib
  rewriter built @rpath references as libQt5QtCore.dylib instead of
  libQt5Core.dylib (it concatenated the libQt5 prefix with the full
  framework basename QtCore). dlopen failed with "Library not loaded:
  @rpath/libQt5QtCore.dylib" on every Mac. Now strips the leading Qt
  from the framework basename before constructing the @rpath name.
* CI guard: workflow now enumerates every @rpath/<file> reference in
  every bundled binary and aborts the build if any of them does not
  resolve to a file actually present in stage/plugins/. Catches the
  next install-name typo at CI time instead of in the field.

EarShield 6.0.6
================

* macOS now ships a dedicated installer .app:
  Install_EarShield_macOS.zip is attached to every release and is the
  recommended install path on macOS. Double-click the .app and confirm
  the install dialog. The installer closes TS3, copies the plugin and
  every bundled dylib into the right plugin folder, clears Gatekeeper
  quarantine, and ad-hoc re-signs each binary.
* Plugin layout flattened on macOS: the .ts3_plugin no longer relies
  on a Frameworks/ subdirectory (TS3's macOS Add-On installer flattens
  subdirs, dropping the Qt frameworks entirely). Qt5Core/Gui/Network/
  Widgets are now extracted as plain libQt5<X>.dylib files alongside
  the plugin dylib, identical to how the Soundboard plugin ships
  bundled FFmpeg.
* Plugin rpath: @loader_path. Every bundled dependency lives next to
  the plugin dylib in plugins/.
* Uninstall script + auto-updater helper updated to wipe every
  lib*.dylib / Qt*.dylib in the plugin folder + remove the legacy
  Frameworks/ subdirectory from older 6.0.x layouts.

EarShield 6.0.5
================

* macOS bundling now recursive: QtCore links libpcre2-16, libzstd,
  libglib, libgthread, etc. from Brew. Those non-Qt /usr/local/*
  dependencies were not bundled in 6.0.4, so QtCore would still fail
  to load on a clean Mac. The .ts3_plugin now ships every transitive
  Brew dylib QtCore + QtGui + QtWidgets + QtNetwork pull in,
  rewritten to @rpath. CI iterates the bundle/rewrite pass up to 8
  rounds and aborts the build if any /usr/local/* reference remains
  in any binary.

EarShield 6.0.4
================

* macOS install name rewrite is now automatic: parses otool -L for
  every /usr/local/* Qt framework reference and rewrites it to @rpath.
  Brew install names point at /usr/local/Cellar/qt@5/<patch>/lib/...,
  not /usr/local/opt/qt@5/lib/..., so the previous static -change
  patterns missed every dependency and the build self-aborted at the
  regression-guard step.

EarShield 6.0.3
================

* macOS plugin load fix (final): TeamSpeak 3 Client.app on macOS does
  not bundle the Qt5 frameworks the plugin links against. v6.0.2's
  @rpath rewrite was correct in form but pointed at frameworks that
  do not exist on the user's machine. The .ts3_plugin now bundles
  QtCore, QtGui, QtNetwork, QtWidgets frameworks in plugins/Frameworks/
  with @loader_path/Frameworks added to the plugin dylib's rpath, so
  the bundled copies resolve directly.

EarShield 6.0.2
================

* macOS plugin load fix (intermediate): rewrote dylib's hardcoded
  Homebrew Qt paths to @rpath. Insufficient on its own — see 6.0.3.

EarShield 6.0.1
================

Highlights
----------
* Cross-platform builds: Windows (x64), Linux (amd64), macOS (Intel x86_64).
* New self-updating channel: EarShield now polls for new releases on startup
  and offers a one-click in-place upgrade. Your settings are preserved across
  updates.
* Single binary per platform: language (English / Italian) is now selectable
  at runtime from the global settings dialog and persisted in EarShield.ini.
  No more separate IT / EN downloads.
* Robust uninstall: TeamSpeak's Settings -> Plugins -> Uninstall now actually
  removes the EarShield binary cleanly. Dedicated uninstall scripts are also
  provided for Windows, Linux, and macOS.
* Legacy file sweep: leftover Volume Leveler files from older installations
  are removed automatically when EarShield starts.

Audio engine (unchanged behaviour, polished)
--------------------------------------------
* Soft-knee per-sample limiter prevents earrape with no audible clipping.
* Slow RMS AGC keeps quiet voices boosted to your target dB.
* Per-client overrides survive reconnects (keyed by TS3 unique identifier).
* Channel commanders are excluded from auto-boost by default; per-client
  toggle remains available.

Configuration
-------------
Plugins -> EarShield Global Settings:
  * Limiter ceiling (dBFS, -30..0)
  * Normalization boost level (dB, 0..30)
  * Enable/disable auto-normalization
  * Language (English / Italiano)
  * Reset native TeamSpeak per-client volumes
  * Reset all EarShield settings to defaults

Right-click any client -> EarShield Client Settings:
  * Per-client limiter ceiling
  * Per-client normalization boost
  * Per-client normalization on/off
  * Reset to global

Right-click any client -> Toggle EarShield Ignore:
  * Bypass EarShield entirely for that client (useful for music bots).

Auto-updater
------------
EarShield checks for updates a few seconds after TeamSpeak loads it. If a
new build is available you are asked whether to update; the helper closes
TeamSpeak, replaces the plugin binary, and the package installer relaunches.
EarShield.ini is never touched during updates.
